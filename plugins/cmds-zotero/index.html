CMDS Zotero 사용설명서

Zotero에서 읽고 표시한 내용을 Obsidian 문헌 노트로 보냅니다. 메타데이터, 하이라이트와 메모, Zotero 노트, 인용과 원문 링크를 한 노트에 모으고, 사람이 쓴 글은 그대로 둡니다. Zotero는 읽기 전용으로 다룹니다.

버전과 공개 상태

2026-10-12에 공개한 CMDS Zotero 0.5.0 기준입니다. GitHub 릴리스에는 CI가 빌드하고 출처를 증명한 main.js, manifest.json, styles.css가 있습니다. Obsidian Community Plugins 목록에는 아직 등록하지 않았습니다. 수동 설치나 BRAT로 설치합니다. 검증 환경은 Obsidian 1.14.4, Zotero 10.0.5, Better BibTeX 9.0.71, macOS입니다. 실제 서재로 최근 읽은 논문 목록, 문헌 노트 생성·갱신 4건, PDF 텍스트 추출 4건(스캔본 1건 포함), 인용문 위치 찾기를 확인했습니다. 그룹 라이브러리와 Windows/Linux는 실사용 검증 범위가 아닙니다.

준비물과 용어

  • Obsidian 데스크톱 1.7.2 이상. 모바일은 지원하지 않습니다.
  • 실행 중인 Zotero와 Better BibTeX(BBT). 플러그인은 BBT의 로컬 JSON-RPC만 사용합니다.
  • 최근 읽은 논문 기능은 Zotero가 PDF를 리더로 열 때 남기는 읽기 기록을 씁니다. Zotero 10에서 확인했습니다.
  • 기본 로컬 주소 http://127.0.0.1:23119/better-bibtex. Zotero Web API 키, native Local API 설정 변경, SQLite 접근, 별도 PDF 도구는 필요 없습니다. citekey는 Example2026 같은 인용 라벨이며 영구 식별자가 아닙니다. 플러그인은 라이브러리 종류, 로컬 library ID, Zotero item key로 항목을 식별합니다. 첨부와 주석은 별도 키를 가지며 부모 항목이 곧 PDF는 아닙니다.

설치

수동 설치

  1. 0.5.0 릴리스에서 main.js, manifest.json, styles.css를 받습니다.
  2. <vault>/.obsidian/plugins/cmds-zotero/ 폴더에 세 파일을 넣습니다.
  3. Obsidian을 다시 로드하고 설정 → 커뮤니티 플러그인에서 CMDS Zotero를 켭니다.

BRAT 설치: BRAT 플러그인에서 johnfkoo951/cmds-zotero를 베타 플러그인으로 추가합니다.

이전 버전에서 올리면 설정(data.json)과 인덱스는 그대로 쓰입니다. 업그레이드 전에 플러그인 폴더를 백업합니다. 옛 플러그인 cmds-link-zotero가 같은 인덱스 경로를 쓰고 있다면 꺼 두어야 인덱스를 갱신할 수 있습니다.

첫 성공: 최근 읽은 논문을 노트로 보내기

  1. Better BibTeX가 켜진 Zotero를 실행합니다.
  2. 설정 → CMDS Zotero에서 Output folder, Image folder, Index path를 볼트 상대경로로 정하고 Save configuration을 누릅니다. Test connection은 저장된 설정을 시험합니다.
  3. 명령 팔레트(Ctrl/Cmd+P)에서 Refresh citekey index를 한 번 실행합니다.
  4. Zotero 리더에서 논문 PDF를 열고 하이라이트나 메모를 남깁니다.
  5. Send recently read papers to notes를 실행하거나 펼친 책 모양 리본 아이콘을 누릅니다.
  6. 목록에서 논문마다 노트 상태를 확인합니다: No literature note yet(노트 없음), N new annotations not in the note(새 주석 N개), Note is up to date(최신), CMDS Zotero가 만들지 않은 노트(덮어쓰지 않음).
  7. 보낼 필요가 있는 논문은 미리 선택되어 있습니다. Send를 누르면 노트를 새로 만들거나 관리 구역만 갱신합니다.
  8. 행의 노트 버튼으로 결과를 열고 주석, 페이지 링크, 메타데이터를 Zotero와 비교합니다.
  9. 노트의 ## Synthesis나 ## Notes에 문장을 쓰고 Zotero에서 하이라이트를 하나 더 한 뒤 다시 보냅니다. 내가 쓴 문장은 그대로 있고 새 주석만 추가되면 첫 성공입니다.

Reading window는 7/30/90/365일 중에서 고릅니다. 기본값은 설정의 Recently read window(30일)입니다. 목록을 보려면 Zotero가 실행 중이어야 합니다.

문헌 노트 가져오기와 갱신

Import literature note는 자료를 골라 미리보기(경로, 구역별 상태, 충돌)를 연 뒤 적용합니다. 자료 선택 창은 최근 읽은 논문을 맨 위에 · read 3 days ago처럼 표시합니다. 가져오기는 저장된 인덱스가 아니라 Zotero의 현재 데이터(그 항목의 export와 첨부·주석)로 노트를 렌더링합니다. 그래서 인덱스를 갱신하지 않아도 방금 단 하이라이트가 들어갑니다. citekey가 Zotero에서 바뀌었으면 item key로 다시 찾고, 다른 항목으로 대체하지 않습니다. Zotero가 꺼져 있으면 저장된 인덱스로 미리보기하고 그 사실을 알립니다. 처음 만드는 노트는 참고문헌 문장이 필요하므로 Zotero가 실행 중이어야 합니다. Update all owned literature notes는 이 플러그인이 만든 노트를 모두 순회하며 관리 구역을 갱신합니다. 결과는 Updated, Partial(편집 구역 보존), Unchanged, Skipped로 보고합니다. 노트마다 승인 창을 열지 않으므로 작은 시험 뒤에 사용합니다.

노트 구조와 보존 규칙

새 노트의 frontmatter에는 type: zotero, zoteroID, zoteroSelectURI, zotero-key, citekey, doi, title, authors, year, tags와 zotero_title 같은 zotero_* 필드가 들어갑니다. frontmatter는 처음 한 번만 만들고 이후에는 사용자 소유입니다. 본문은 다음 순서입니다.

  • 제목과 초록(overview), 참고문헌(citation)
  • ## Synthesis: 사용자 영역(**Contribution**::, **Related**::)
  • 메타데이터와 링크(metadata): 저자, 학술지, DOI, URL, 태그, 컬렉션, Zotero 관련 항목, Zotero와 PDF 열기 링크
  • ## Zotero notes(notes): Zotero 자식 노트를 제목·목록·링크를 살린 Markdown으로 넣습니다. 코드 블록은 그대로 둡니다.
  • ## Notes: 사용자 영역
  • ## Annotations: 주석마다 블록 하나. Zotero의 읽기 순서대로 놓이고, 나중에 앞쪽 페이지에 단 주석도 제자리에 들어갑니다. 하이라이트, 밑줄, 이미지, 메모, 손그림(ink)을 구분하며 페이지 링크는 Zotero 리더의 해당 위치를 엽니다.

관리 구역은 <!-- cmds-zotero:<id>:<해시> -->와 <!-- /cmds-zotero:<id> --> 사이입니다. 관리 구역을 고치면 그 구역만 **편집됨(보존)**으로 남고 나머지는 갱신됩니다. 미리보기에서 구역마다 다음 중 하나를 고릅니다.

  • Keep this time: 이번에는 그대로 둡니다.
  • Detach: 그 블록을 영구히 내 것으로 만듭니다. 다시 렌더링하지 않습니다.
  • Reset from Zotero: Zotero 내용으로 되돌립니다. 이전 노트는 .cmds-zotero/backups/notes/에 백업합니다. 마커가 손상되었거나, 중복되었거나, CMDS Zotero가 만들지 않은 노트이거나, 같은 식별을 가진 노트가 여럿이면 쓰지 않고 이유와 줄 번호를 보여 줍니다. Zotero에서 지운 주석의 블록은 노트에서 지우지 않습니다.

인용, 참고문헌, 사이드바

  • Insert citation from Zotero: BBT의 Cite As You Write 선택기로 인용을 넣습니다. 기본 형식은 [@citekey]입니다.
  • 편집기에서 [@ 뒤에 citekey·제목·저자·연도 일부를 입력하면 로컬 자동완성이 나옵니다. 캐시된 인덱스를 읽으므로 키 입력마다 Zotero를 부르지 않습니다.
  • Open references sidebar: 현재 노트의 [@key], @key, 인용 위키링크를 모아 참고문헌과 미해결 상태를 보여 줍니다. Zotero가 꺼져 있어도 저장된 참고문헌(.cmds-zotero/bibliography.json)으로 표시합니다.
  • Open annotations sidebar: 현재 문헌 노트나 고정한 자료의 주석을 보고 커서 위치에 넣거나 복사합니다.
  • Insert bibliography: 자료 하나의 CSL 참고문헌을 편집기에 넣습니다.
  • Copy CSL-JSON for cited sources와 Write pandoc bibliography sidecar for current note: 현재 노트가 인용한 자료를 CSL-JSON으로 복사하거나 .cmds-zotero/bibliography/<노트>.json에 저장하고, frontmatter에 넣을 bibliography: 줄을 알려 줍니다. pandoc으로 DOCX를 만드는 방법은 pandoc/DOCX 가이드에 있습니다.

PDF 텍스트와 에이전트

AI 에이전트와 스크립트는 같은 기능을 CLI로 씁니다. CLI는 실행 중인 Obsidian의 플러그인에 작업을 맡기고, 가능한 읽기 작업은 Obsidian 없이 인덱스 파일로 답합니다.

node scripts/ingest.mjs --vault "Research" --action recent --days 30
node scripts/ingest.mjs --vault "Research" --action import --citekey Example2026
node scripts/ingest.mjs --vault "Research" --action import --citekey Example2026 --apply
node scripts/ingest.mjs --vault "Research" --action pdf-text --citekey Example2026 --pages 1-3
node scripts/ingest.mjs --vault "Research" --action locate --citekey Example2026 --quote "quoted text"
  • recent는 읽은 날짜와 노트 상태(none, behind, current, foreign, duplicate)를 돌려줍니다.
  • import는 --apply가 없으면 미리보기만 합니다. 하드 충돌은 note-conflict로 거절합니다. Zotero에서 실시간으로 읽지 못하면 --allow-stale 없이는 쓰지 않습니다.
  • pdf-text는 Obsidian에 내장된 pdf.js로 텍스트를 뽑아 비공개 캐시(.cmds-zotero/pdf-text/)에 저장합니다. 한·중·일 글꼴용 문자 지도를 함께 씁니다. 텍스트 레이어가 없는 스캔본은 textLayer: none과 OCR 권장 경고를 냅니다. 페이지마다 반복되는 워터마크는 본문으로 세지 않습니다.
  • locate는 인용문이 있는 쪽을 찾아 Zotero 리더 링크와 함께 돌려줍니다.
  • 읽기 전용 환경에서는 scripts/ingest-ro.mjs를 씁니다. 쓰기와 --apply를 거절합니다. 에이전트는 관리 구역을 직접 고치지 않고, 자기 요약은 ## Synthesis나 ## Notes에 씁니다. 전체 규약은 에이전트 계약에 있습니다.

교차 볼트와 Hookmark

Peer vaults에 등록한 다른 볼트의 노트 지도를 읽기 전용으로 읽고 Find literature across vaults로 이동합니다. 같은 citekey라도 다른 볼트에서는 다른 자료일 수 있으므로 식별을 확인합니다. Hookmark 관련 명령은 링크를 클립보드에 복사할 뿐입니다. Hookmark 설정을 바꾸거나 북마크를 만들거나 스크립트를 실행하지 않습니다.

데이터와 개인정보

  • 로컬 BBT에 메타데이터, 인용, 참고문헌, 첨부와 주석, 읽기 기록을 요청합니다. Zotero 설정, 데이터베이스, citekey, 라이브러리 기록은 바꾸지 않습니다.
  • 이미지 주석을 가져오면 볼트 밖의 Zotero 캐시 이미지를 읽어 이미지 폴더에 복사합니다.
  • 볼트에 쓰는 것은 설정, 인덱스, 문헌 노트, 이미지 사본, .cmds-zotero/ 아래의 비공개 파일(참고문헌·노트 지도·백업·PDF 텍스트 캐시)입니다. 플러그인은 .cmds-zotero/.gitignore를 먼저 만들어 이 폴더가 git에 올라가지 않게 합니다. PDF 텍스트 캐시는 논문 전문이므로 공유하지 않습니다.
  • 인덱스와 노트 지도에는 서지정보, 개인 경로, 주석이 들어갈 수 있습니다. 공개 저장소에 올리지 않습니다.
  • 텔레메트리, 자체 HTTP 서버, 자동 업데이트는 없습니다.

CMDS Zotero user guide

Send what you read and mark up in Zotero to Obsidian literature notes. Metadata, highlights and comments, Zotero notes, citations and links back to the source end up in one note, and the text you write yourself stays untouched. Zotero is treated as read-only.

Version and release status

This guide covers CMDS Zotero 0.5.0, released on 2026-10-12. The GitHub release carries main.js, manifest.json and styles.css, built and attested by CI. The plugin is not yet listed in Obsidian Community Plugins; install it manually or with BRAT. It was verified with Obsidian 1.14.4, Zotero 10.0.5 and Better BibTeX 9.0.71 on macOS. Checks on a real library covered the recently read list, creating and updating four literature notes, PDF text extraction for four papers (one of them a scan) and quote location. Group libraries and Windows/Linux are outside the verified scope.

Requirements and terms

  • Obsidian desktop 1.7.2 or later. Mobile is not supported.
  • A running Zotero with Better BibTeX (BBT). The plugin talks only to BBT's local JSON-RPC.
  • Recently read papers use the reading history Zotero records when a PDF opens in its reader; this was verified on Zotero 10.
  • The default local endpoint is http://127.0.0.1:23119/better-bibtex. No Zotero Web API key, native Local API setting, SQLite access or separate PDF tool is needed. A citekey such as Example2026 is a citation label, not a permanent identifier. The plugin identifies an item by library type, local library ID and Zotero item key. Attachments and annotations have their own keys; a parent item is not a PDF.

Installation

Manual

  1. Download main.js, manifest.json and styles.css from the 0.5.0 release.
  2. Put the three files in <vault>/.obsidian/plugins/cmds-zotero/.
  3. Reload Obsidian and enable CMDS Zotero under Settings → Community plugins.

BRAT: add johnfkoo951/cmds-zotero as a beta plugin in BRAT.

Upgrading keeps your settings (data.json) and index. Back up the plugin folder first. If the old cmds-link-zotero plugin shares the index path, disable it, or index refreshes are refused.

First success: send recently read papers to notes

  1. Start Zotero with Better BibTeX enabled.
  2. In Settings → CMDS Zotero, set Output folder, Image folder and Index path (vault-relative) and press Save configuration. Test connection tests the saved settings.
  3. Run Refresh citekey index once from the command palette (Ctrl/Cmd+P).
  4. Open a paper's PDF in Zotero's reader and add a highlight or a comment.
  5. Run Send recently read papers to notes, or click the open-book ribbon icon.
  6. Each row shows the state of its literature note: No literature note yet, N new annotations not in the note, Note is up to date, or a note CMDS Zotero did not create (never overwritten).
  7. Papers that need sending are preselected. Send creates the note or refreshes only its managed sections.
  8. Open the result with the row's note button and compare annotations, page links and metadata with Zotero.
  9. Write a sentence under ## Synthesis or ## Notes, add another highlight in Zotero and send again. Your sentence stays and only the new annotation is added: that is the first success.

The Reading window offers 7, 30, 90 or 365 days; the default is the Recently read window setting (30 days). Zotero must be running for the list.

Importing and updating literature notes

Import literature note lets you pick a source, shows a preview (path, per-section states, conflicts) and applies it. The picker lists recently read papers first, labelled like · read 3 days ago. Imports render from Zotero's current data (that item's export plus its attachments and annotations), not from the saved index, so highlights made a minute ago are included without refreshing the index. If the citekey changed in Zotero, the item is found again by item key; another item is never substituted. With Zotero closed, the preview uses the saved index and says so. Creating a new note needs bibliography text, so Zotero must be running for a first import. Update all owned literature notes walks every note this plugin created and refreshes its managed sections, reporting Updated, Partial (edited sections preserved), Unchanged and Skipped. It does not ask per note, so run it after a small test.

Note layout and preservation

A new note's frontmatter holds type: zotero, zoteroID, zoteroSelectURI, zotero-key, citekey, doi, title, authors, year, tags and the zotero_* fields such as zotero_title. Frontmatter is written once and is yours afterwards. The body follows this order:

  • Title and abstract (overview), bibliography text (citation)
  • ## Synthesis: your area (**Contribution**::, **Related**::)
  • Metadata and links (metadata): creators, journal, DOI, URL, tags, collections, related Zotero items, links that open Zotero and the PDF
  • ## Zotero notes (notes): Zotero child notes as Markdown with headings, lists and links kept; code blocks pass through unchanged
  • ## Notes: your area
  • ## Annotations: one block per annotation, in Zotero's reading order, so an annotation added later on an earlier page still lands in place. Highlights, underlines, images, comments and ink drawings are distinguished, and page links open that spot in Zotero's reader.

Managed sections sit between <!-- cmds-zotero:<id>:<hash> --> and <!-- /cmds-zotero:<id> -->. If you edit one, only that section is kept as edited (preserved) while the rest of the note updates. In the preview you choose per section:

  • Keep this time: leave it as it is for this update.
  • Detach: make the block permanently yours; it is never rendered again.
  • Reset from Zotero: replace it with Zotero's content; the previous note is first backed up to .cmds-zotero/backups/notes/. Damaged or duplicate markers, a note CMDS Zotero did not create, or several notes with one identity block the write, with the reason and line number shown. Blocks for annotations deleted in Zotero are never removed from the note.

Citations, bibliographies and sidebars

  • Insert citation from Zotero uses BBT's Cite As You Write picker; the default format is [@citekey].
  • Typing part of a citekey, title, author or year after [@ in the editor opens local completion. It reads the cached index, so Zotero is not called on every keystroke.
  • Open references sidebar collects [@key], @key and citation wikilinks in the current note and shows their bibliography and unresolved states. With Zotero closed it uses saved bibliography text (.cmds-zotero/bibliography.json).
  • Open annotations sidebar shows the annotations of the current literature note or a pinned source, to insert at the cursor or copy.
  • Insert bibliography inserts one source's CSL bibliography text.
  • Copy CSL-JSON for cited sources and Write pandoc bibliography sidecar for current note copy the current note's cited sources as CSL-JSON, or save them to .cmds-zotero/bibliography/<note>.json and show the bibliography: line for the frontmatter. The pandoc/DOCX guide explains the export.

PDF text and agents

AI agents and scripts use the same features through the CLI. It hands work to the plugin in the running Obsidian and answers read-only requests from the index file when Obsidian is not available.

node scripts/ingest.mjs --vault "Research" --action recent --days 30
node scripts/ingest.mjs --vault "Research" --action import --citekey Example2026
node scripts/ingest.mjs --vault "Research" --action import --citekey Example2026 --apply
node scripts/ingest.mjs --vault "Research" --action pdf-text --citekey Example2026 --pages 1-3
node scripts/ingest.mjs --vault "Research" --action locate --citekey Example2026 --quote "quoted text"
  • recent returns read days and note states (none, behind, current, foreign, duplicate).
  • import previews only unless --apply is given. Hard conflicts are refused with note-conflict. If Zotero cannot be read fresh, nothing is written unless --allow-stale is given.
  • pdf-text extracts text with Obsidian's bundled pdf.js into a private cache (.cmds-zotero/pdf-text/), with the character maps CJK fonts need. A scan without a text layer reports textLayer: none and an OCR warning; watermarks repeated on every page are not counted as body text.
  • locate finds the page of a quote and returns a link into Zotero's reader.
  • In read-only contexts use scripts/ingest-ro.mjs, which refuses writes and --apply. Agents never edit managed sections; their own summaries go under ## Synthesis or ## Notes. The full rules are in the agent contract.

Cross-vault and Hookmark

The plugin reads the note maps of vaults listed in Peer vaults, read-only, and Find literature across vaults opens them. The same citekey in another vault can be a different source, so check the identity. The Hookmark commands only copy links to the clipboard. They do not change Hookmark settings, create bookmarks or run scripts.

Data and privacy

  • The plugin asks the local BBT for metadata, citations, bibliographies, attachments and annotations, and reading history. It never changes Zotero settings, the database, citekeys or library records.
  • Importing image annotations reads Zotero's cached images outside the vault and copies them into the image folder.
  • In the vault it writes settings, the index, literature notes, image copies and private files under .cmds-zotero/ (bibliography, note map, backups, PDF text caches). It creates .cmds-zotero/.gitignore first so the folder stays out of git. PDF text caches hold full paper text; do not share them.
  • The index and note map can contain bibliographic data, private paths and annotations. Keep them out of public repositories.
  • No telemetry, own HTTP server or self-updater.

Troubleshooting

Symptom Check
The recently read list is empty Zotero is running, the reading window, and the PDF was opened in Zotero's reader
A new highlight is missing from the note Zotero is running; with Zotero closed the saved index is used
A note is refused as "not created by CMDS Zotero" Another plugin created it; it is never overwritten, so check the output folder and file name
Import blocked by damaged markers Fix the marker at the line shown in the preview, or use Reset
Index refresh refused Whether the old cmds-link-zotero plugin is enabled
Connection fails Zotero and BBT are running, the localhost endpoint, timeouts
A PDF opens on the wrong page Page numbers are file positions, not printed labels
pdf-text returns nothing The textLayer value; none means a scan that needs OCR

Migrating from the old plugin ID

To move from cmds-link-zotero, quit Obsidian and run scripts/migrate-local.mjs as dry-run, then check, then apply, with a new private backup folder outside the vault and the repository.

node scripts/migrate-local.mjs --vault /path/to/vault --backup /path/to/private-backups/migration-001 --mode dry-run
node scripts/migrate-local.mjs --vault /path/to/vault --backup /path/to/private-backups/migration-001 --mode check
node scripts/migrate-local.mjs --vault /path/to/vault --backup /path/to/private-backups/migration-001 --mode apply --expect CHECK_FINGERPRINT

rollback mode undoes it and refuses to overwrite files changed after deployment. Afterwards check that only the new ID is enabled and rebuild the index.
